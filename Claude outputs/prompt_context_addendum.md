# Дополнение к промту: контекст проекта

Приложение к задаче «оформить финальное решение `disentangle_b2_li760_r8_all_data_hard_pixel_ft`».
Всё ниже — состояние на 17.09.2026. Цифры и имена файлов **проверять по репозиторию**:
часть восстановлена из проектных доков, репозиторий — источник истины.

---

## 1. Задача и ограничения

- Соревнование AIIJC 2026, трек AIC: по JPEG-изображению предсказать бинарную маску
  области, изменённой ИИ.
- Метрика **AIC Score** — гармоническое среднее Dice (по позитивам) и 1−FPR (по негативам).
- Жёсткие лимиты, нарушение = дисквалификация: **≤100 GFLOPs на изображение** и
  **≤50 мс на H100**. GFLOPs считаются `FlopCounterMode` только по форварду модели;
  DCT-препроцессинг и восстановление маски в счёт не входят — держать запас.
- Правила: аугментации разрешены, **сторонние датасеты запрещены**.
- Сабмит: `submission.csv` + папка `predictions/` с масками, в корне zip без вложенной папки.

## 2. Репозиторий

`curly-guacamole` — основной. `experimental-tools-beliy-russak` — старая библиотека,
оттуда тянуть материал для EDA и для сравнения старых моделей.

```
src/                 модель, данные, обучение, инференс
  config.py          строгая валидация YAML — лишний ключ это ошибка, не тихий игнор
  decoders/          мини-реестр в духе timm: @register_decoder, create_decoder, list_decoders
  modules/           forensic_disentangle.py, fft_branch.py, fft_fusion.py и т.п.
  training/engine.py run_experiment(config) -> run.summary
  inference.py       python -m src.inference runs/<run> submissions/<run>
  budget.py          count_gflops (= FlopCounterMode)
configs/             baseline.yaml, baseline_long.yaml в корне (это проверяет тест
                     test_baseline_cleanup); армы — в configs/experiments/
notebooks/           один ноутбук на серию экспериментов, не на каждый run
runs/<run_name>/     summary.json, metrics.csv, notes.md, ckpt/best.pt, EMA-веса
tests/               pytest на синтетике, без скачивания весов и без датасета
global_config.py     DATA_PATH
```

Запуск обучения из кода:

```python
from src.config import load_experiment_config
from src.training.engine import run_experiment
run = run_experiment(load_experiment_config("configs/....yaml"))
```

Инференс: `python -m src.inference runs/<run_name> submissions/<run_name>` — берёт
`ckpt/best.pt`, сохранённый конфиг и подобранные на валидации пороги из `summary.json`.
Пороги переопределяются только все три сразу: `--mask-threshold`, `--cls-threshold`, `--min-area`.

Окружение: conda `challenges` (Python 3.11, torch/torchvision, timm, albumentations,
opencv-python-headless). **В solution.ipynb зависимости ставятся внутри ноутбука** —
это требование регламента, иначе 0 баллов за весь этап.

## 3. Архитектура финального решения

Линия `disentangle_b2_li760_r8_*`. Расшифровка имени — проверить по конфигу:
`b2` = энкодер `pvt_v2_b2`, `li760` = `resize_mode: letterbox`, `image_size: 760`,
`r8` = `model.disentangle_reduction: 8`, `all_data` = обучение на train+development,
`hard` = работа с трудной стратой `plain/nonunit`, `pixel` = пиксельные region-лоссы,
`ft` = финальная стадия дообучения.

Состав модели:

- **Энкодер** PVTv2-b2 (timm), пирамида страйдов 4/8/16/32, каналы 64/128/320/512.
- **Декодер** slim U-Net, `decoder_channels (128,64,32,16,16)`, плюс `GateHead`
  (покадровый классификатор «есть ли правка»).
- **DCT-ветка** (`forensic_mode: jpeg`) — читает квантованные коэффициенты Y прямо из
  контейнера JPEG, сливается с фичами энкодера на страйдах 8/16/32. Оптимизирована
  lookup-таблицей + Triton-ядром (one-hot dilated conv заменён на categorical gather),
  освободило ~30 GFLOPs.
- **DG-Force disentangle** (`src/modules/forensic_disentangle.py`) — PFD (patch-ветка,
  канальное горлышко 1×1 C→C/r→C) и EFD (edge-ветка, depthwise-separable), головы
  плотной супервизии **только в training** (на инференсе их нет в графе), per-token
  баланс softmax и `channel_gate` с **нулевой инициализацией**: необученный арм побитово
  равен базе, а вклад снимается занулением гейта.
- Опционально cross-scale attention на страйдах 16/32.

Бюджет (замер на ветке `codex/jpeg640-baseline`, вход 640, нативный кадр 1024²):
`baseline` 90.5714, арм S +0.0000, арм D +0.3126, арм M +0.5846 GFLOPs.
**Для 760 бюджет пересчитать заново** — цифры выше не переносятся.

Ручки: `model.disentangle_levels` (`[]` = выключен), `disentangle_mode`
(`supervision` | `fuse`), `disentangle_cross_strides` (страйд 8 стоит 15 GFLOPs — только
16 и 32), `disentangle_reduction`, `disentangle_attention_width`/`_heads`,
`loss.patch_weight` / `edge_weight` / `edge_band` / `edge_max_pos_weight`,
`loss.false_region_weight` / `false_region_threshold` / `false_region_margin`,
`loss.contrast_weight` + `model.contrast_head`.

Конфиг падает с ValueError, а не игнорирует молча: cross без levels, cross в режиме
supervision, cross-страйд не из levels, супервизия без модуля, чётная полоса границы.

## 4. Данные

Домены и их поведение (по разбору ошибок):

| домен | Dice | разрешение | qt_luma | комментарий |
|---|---|---|---|---|
| plain_l8 | 0.925 | 640 | 1.00 | лучший разрез, все негативы домена здесь |
| coco | 0.912 | 640 | 1.00 | взял 96% от потолка разметки (0.9455) |
| raise | 0.890 | 1024 | 5.77 | |
| numid | 0.799 | 500 | 1.00 | inpainted |
| openimages | 0.780 | 1024 | 5.77 | |
| vision | 0.774 | 1024 | 1.00 | inpainted |
| **plain_l9** | **0.570** | 1024 | **15.02** | 23% кадров, **половина всего недобора Dice** |

Ключевые факты для EDA:

- `plain` — это **два разных датасета**. `plain_l8` (есть hash-префикс) и `plain_l9`
  (9 цифр в stem, без префикса). В `l9` ноль негативов и `has_src = 0`.
- `qt_luma >= 8` — детектор `plain_l9` с precision 1.000, recall 0.879. Читается из
  заголовка JPEG, стоит ноль GFLOPs. В тесте подысточник в той же пропорции (22.0%).
- Гипотезы, которые **проверены и закрыты** (не переоткрывать в EDA):
  `Resize` губит мелкие маски — нет (потолок круговорота GT 0.9985); грубая граница —
  нет (полоса ±3 px это 8.5% площади); шум разметки — нет (кадров с покрытием <50%
  всего 0.2%); порог бинаризации GT — нет (Dice@64 против @128 = 0.999+); у `plain_l9`
  другая разметка — нет (морфология масок как у соседей, отличие только мягкая кромка
  у 4.3% пикселей); утечка между фолдами — нет (~0.0003).
- Трудность принадлежит **изображению, а не правке**: ICC = 0.533, R² ≈ 0.50 по одним
  свойствам файла на пяти разных моделях.
- Разрыв val → test: −0.005…−0.017, одинаков во всех пяти фолдах, сидит в весе файла
  (тестовые кадры на 11–13% легче при том же разрешении).

## 5. Методология — это и есть критерий на 2,1–3 балла

- **Один фактор на плечо**, и проверять по коду, а не по комментарию. Исторический
  провал: плечо H отвечало на два вопроса сразу (`aux_weight=0.4` был намертво связан
  с `model="hf"`).
- **Сравнение плеч по одной итоговой цифре мертво.** σ между двумя одинаковыми
  прогонами ≈ 0.0078–0.011. Эффект 0.0032 потребовал бы 48 прогонов. Работает только
  **парное покадровое сравнение** с бутстрэп-интервалом и разрезы по доменам/корзинам площади.
- **Модуль в forward-пути меряется абляционной дельтой внутри прогона** (занулить
  `channel_gate` на готовом чекпоинте, второй проход по development): разрешение 0.0001
  против σ = 0.0078. Супервизию абляцией измерить нельзя — её нет в forward.
- **Любая проба на готовом чекпоинте начинается с воспроизведения уже известной цифры
  этого чекпоинта.** Полминуты против часа мусора: `load_state_dict(strict=False)`
  однажды проглотил несовпадение архитектуры, ноутбук отработал без ошибок и выдал
  правдоподобные таблицы случайно инициализированной модели.
- Три несовместимые валидации в `runs/` (5006/643, 5022/632, 20101/639) уже сравнивались
  как одна. **В снапшот писать версию фолдов и размер валидации**; в
  `model_comparison.ipynb` цифры из разных стендов рядом не ставить без явной пометки.
- Постобработка исчерпана: адаптивный порог +0.0019, площадной гейт +0.0010 с интервалом,
  касающимся нуля, оптимизм самой калибровки +0.0014. Направление закрыто.
- Закрыто как контрпродуктивное: distance-based лоссы (boundary, Hausdorff, centroid,
  `w_far`) — «пусто» доминирует над «мимо» в 1.7 раза, и дистанционные штрафы подавляют,
  а не переносят предсказание.

## 6. Что пойдёт в ноутбуки

**`notebooks/eda.ipynb`** — распределение доменов и площадей масок, разделение
`plain_l8`/`plain_l9` по stem, `qt_luma` из заголовка JPEG как метка поддатасета,
корзины площади, потолок круговорота GT, сравнение статистик train/val/test (вес файла!),
негативы по доменам. Часть кода есть в `experimental-tools-beliy-russak`.

**`notebooks/model_comparison.ipynb`** — поверх `runs/`. Сравнение линий: ConvNeXt-tiny
U-Net → HF-ветка (SRM+Bayar) → YOLO26-sem → STDC1-Seg → PVTv2-b2 → `jpeg576` →
`disentangle`. Обязательно: пометка, на каком стенде мерилась каждая строка; парные
покадровые сравнения там, где есть сохранённые покадровые Dice; GFLOPs рядом с AIC.

**`notebooks/ablations.ipynb`** — иерархия путей (ботлнек / скипы s4, s8, s16 / ветка),
абляционная дельта `channel_gate`, вклад DCT-ветки, линейные зонды до s16 и s32 против
модели, таксономия отказов («слепа» / «гейт стёр» / «мимо» / «частично» / «неточно» / «ок»)
и её вклад в недобор AIC, разбивка по `plain_l9`.

Идеи и прогоны делить на **«с GPU»** и **«без GPU»** — часть проб (разбор сохранённых
карт вероятностей, статистика по файлам, бюджет GFLOPs) считается на CPU.

## 7. Форматы и соглашения

- Ноутбуки — **jupytext py:percent**, по образцу существующих в `notebooks/`.
- Комментарии и markdown — по-русски.
- Отдельные markdown-ячейки с меткой `TODO:` под ручную правку текста.
- **Не писать свои реализации известных алгоритмов** (хеши, LSH, union-find, connected
  components и т.п.) — брать готовые пакеты (scipy, skimage, timm, albumentations).
- Выводы — тезисно и простым языком.
- Сиды фиксировать явно (torch, numpy, random, `torch.backends.cudnn.deterministic`) —
  это прямо назван пункт в критериях оценки.

## 8. Грабли, которые ломают воспроизводимость

- **T4 (Turing, sm_75) не имеет аппаратного bf16** и молча эмулирует его в разы медленнее
  — использовать fp16. Проверка `torch.cuda.is_bf16_supported()`.
- `resize_mode: letterbox` и `stretch` — **разная геометрия**; переключение на
  существующем `run_name` при `resume` запрещено и падает.
- `eval.resolution: original` — метрика и пороги считаются на исходном размере маски;
  бейзлайны с разным режимом напрямую не сравнивать.
- **`summary.json` класть рядом с чекпоинтом** — иначе проверка вменяемости в ноутбуках
  молча пропускается.
- Ultralytics берёт масштаб модели из **имени файла** по регулярке `yolo26[nsmlx]`, а не
  из ключа `scale` в YAML. В semantic-режиме значение 255 в маске = «ignore», GT надо
  ремапить в `{0,1}`.
- Группировка параметров: сначала проверять **принадлежность группе**, потом decay.
  Проверка `p.ndim <= 1` первой отправляет все LayerNorm/LayerScale энкодера на полный lr.
- Зануление skip-каналов — **после** инициализации Kaiming, не до.
- Xavier не подходит для ReLU/GELU; нужен Kaiming с `nonlinearity="relu"`.
- `batch["dist"]` датасетом не считается — арм, который на него опирается, падает в рантайме.
- `mit_*` не строятся на `meta`-устройстве — ячейке бюджета нужен фолбэк на CPU.
- Площадь для сэмплера берётся **до** кропа; `sample_crop` меняет видимую долю маски почти
  втрое либо обнуляет её.
- Сэмплеры по доле домена и по доле площади должны быть **взаимно исключающими**.
- `notebooks/16_forensic_maps_before_resize.ipynb` — архив, не рабочая точка входа.
